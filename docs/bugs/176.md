# BUG-176 — C-ABI embedding surface missing

- **Severity:** `MED` — design gap, not a runtime bug; the Zig-side API is
  complete, but luazig is not a drop-in `liblua.a` for C consumers.
- **Status:** ✅ FIXED
- **Location:** `src/lstate.zig` (`luaL_newstate`, `lua_close`),
  `src/lualib.zig` (`luaopen_*` openers).

## Defect Summary

The reference exports C-callable `lua_newstate`/`lua_newstateat`,
`lua_close`, and `luaopen_*` symbols. `luazig` had only Zig-side
constructors that require a `std.mem.Allocator` argument and Zig-internal
openers; nothing was `extern`-callable from C.

## Resolution

1. Added `is_c_allocated: bool = false` to `lua_State` in `src/lua.zig`.
2. Implemented and exported C-ABI symbols `luaL_newstate`, `lua_newstate`, and `lua_close` in `src/lstate.zig`. When allocated via `luaL_newstate()` / `lua_newstate()`, `L` is allocated on the heap via `std.heap.c_allocator` and automatically freed upon `lua_close(L)`.
3. Exported all standard library openers with C linkage (`luaopen_base`, `luaopen_package`, `luaopen_coroutine`, `luaopen_table`, `luaopen_string`, `luaopen_math`, `luaopen_os`, `luaopen_io`, `luaopen_debug`, `luaopen_bit32`, `luaopen_utf8`) in `src/lualib.zig`.
4. Verified with unit test `BUG-176: C-ABI embedding entry points luaL_newstate, lua_close, luaopen_*` in `tests/test_basic.zig`.
