# BUG-150 — `os.tmpname` Rapid Deterministic Filename Collisions via Second-Resolution Timestamp

- **Severity:** `MED`
- **Status:** ✅ FIXED
- **Location:** `src/lib/oslib.zig:121-130` (`os_tmpname`)

## Defect Summary

In `src/lib/oslib.zig`:
```zig
fn os_tmpname(L_: *L) !i32 {
    var buf: [64]u8 = undefined;
    const seed = if (L_.l_G) |g| g.seed else 0;
    const ptr_val = @intFromPtr(L_);
    var t: TimeT = 0;
    _ = time(&t);
    const path = std.fmt.bufPrint(&buf, "/tmp/lua_{x}_{x}_{x}", .{ t, seed, ptr_val & 0xFFFF }) catch "/tmp/lua_tmp";
    _ = lua.lua_pushlstring(L_, path, path.len);
    return 1;
}
```

Within a single running Lua state:
- `seed` is static (fixed at state initialization).
- `ptr_val` is static (pointer to `lua_State`).
- `time(&t)` only updates once per second.

If a script or library invokes `os.tmpname()` twice in succession within the same second (e.g. creating two temporary files during test setup or data transformation):
Both calls produce **byte-identical file paths**.

## Impact

Rapid successive calls to `os.tmpname()` collide immediately, causing file overwrite bugs, race conditions, or unhandled file creation failures in caller applications.

## Proposed Fix

Incorporate a monotonic counter stored on `global_State` (or draw random bytes from the state's PRNG `g.prng_state` / `std.os.linux.getrandom`):
```zig
const count = g.next_tmpname_id;
g.next_tmpname_id +%= 1;
... bufPrint(&buf, "/tmp/lua_{x}_{x}_{x}_{x}", .{ t, seed, ptr_val & 0xFFFF, count });
```
