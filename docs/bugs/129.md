# BUG-129 — CLI divergences from the reference standalone interpreter

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `src/luazig.zig` (option handling, error reporting);
  `src/lua.zig:5799-5814` (`createargtable`); reference: `lua/lua.c`
  (`handle_script`, `collectargs`, `createargtable`).
- **Defect:**
  1. `LUA_INIT` / `LUA_INIT_5_5` environment variables are not consulted at
     startup and there is no `-E` switch to ignore them (C lua.c runs the init
     chunk before the script).
  2. Uncaught-error output lacks the `progname: ` prefix — differential runs show
     `./lua/lua: file:N: msg` vs port `file:N: msg`.
  3. `createargtable` maps only `[0]=script` and `[1..]=post-script args`; C also
     records interpreter/options args at negative indices (`arg[-1]`, …).
- **Impact:** Drop-in divergence for scripts relying on `LUA_INIT` startup hooks,
  on `arg[-n]` introspection, or on output formats parsed by test harnesses.
- **Proposed fix:** Port `handle_luainit`/`-E`, prepend program name in the
  top-level message handler, and extend `createargtable`.
