# BUG-134 — `std.debug.print` for runtime warnings / loader diagnostics

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `src/lua.zig:1428` (stack shrink), `4811` (`luaC_condGC`
  failure), `5168` (`__gc` finalizer error); `src/lundump.zig:304,312,319`
  (`checkHeader` mismatch details printed to stderr rather than encoded into the
  returned error/message object).
- **Defect:** §0.1 rule 10 requires user-facing output to flow through the
  `io: std.Io` threaded from state creation. These sites write directly to
  stderr; the lundump printers additionally duplicate information that belongs in
  the Lua-level error string pushed by `lua_load` (which currently collapses all
  messages — see BUG-116).
- **Impact:** Warnings cannot be redirected/suppressed by embedding applications;
  header-mismatch detail never reaches the Lua programmer.
- **Proposed fix:** Route warnings through a state-configurable warn function
  (`lua_setwarnf` exists since H-phase) and fold header diagnostics into the
  error message.
