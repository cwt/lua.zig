# BUG-130 — `LUA_ERRFILE` constant collision / removed-upstream

- **Severity:** [LOW]
- **Status:** ✅ FIXED

- **Location:** `src/lauxlib.zig:581` (`pub const LUA_ERRFILE: i32 = 5`) vs
  `src/llimits.zig:44` (`LUA_ERRERR: i32 = 5`). Reference `lua/lauxlib.h:27`
  defines `#define LUA_ERRFILE (LUA_ERRERR+1)` (= 6).
- **Defect:** `LUA_ERRFILE` in `src/lauxlib.zig` was set to 5 instead of `(LUA_ERRERR + 1)` (= 6),
  colliding with `LUA_ERRERR`. Furthermore, `luaL_loadfilex` was returning `LUA_ERRERR` instead
  of `LUA_ERRFILE` when failing to open a file.
- **Impact:** Latent misinterpretation of `luaL_loadfilex` statuses; failure to distinguish file open errors from error handler aborts.
- **Proposed fix:** Set `LUA_ERRFILE = LUA_ERRERR + 1` (6) matching `lua/lauxlib.h:27` and return it from `luaL_loadfilex`.
- **Fix:** Defined `LUA_ERRFILE = LUA_ERRERR + 1` (6) in `src/llimits.zig`, re-exported in `src/lua.zig` and `src/lauxlib.zig`, and updated `luaL_loadfilex` to return `LUA_ERRFILE`. Added unit test in `tests/test_basic.zig`.
