# BUG-130 — `LUA_ERRFILE` constant collision / removed-upstream

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `src/lauxlib.zig:613` (`pub const LUA_ERRFILE: i32 = 5`) vs
  `src/llimits.zig:44` (`LUA_ERRERR: i32 = 5`). Reference `lua/lua.h:50-53`
  defines only ERRRUN(2)/ERRSYNTAX(3)/ERRMEM(4)/ERRERR(5) — no ERRFILE.
- **Defect:** The invented constant shares its value with `LUA_ERRERR`. Any
  consumer switching on status codes cannot distinguish a file-level load failure
  from an error-in-error-handling condition; code that mirrors upstream headers
  will not compile against this name/value pair either way.
- **Impact:** Latent misinterpretation of `lua_load`/`luaL_loadfilex` statuses;
  ABI-conformance noise for embedders porting C code.
- **Proposed fix:** Remove `LUA_ERRFILE` (matching 5.5) or renumber distinctly;
  grep call sites for reliance on the value.
