# BUG-139 — `finishLoad` GC Object Dangling Pointers, UAF, and Double-Free on OOM

- **Severity:** `CRITICAL`
- **Status:** ⏳ OPEN
- **Location:** `src/lua.zig:4119-4183` (`finishLoad`)

## Defect Summary

During prototype closure instantiation in `finishLoad`:
1. Each upvalue `uv` is allocated and immediately registered into the garbage collector via `try registerGC(L, uv)` (linking it to `g.allgc`).
2. If allocating or registering any subsequent upvalue fails (`i > 0`), lines 4140–4142 and 4156–4158 execute:
   ```zig
   for (0..i) |j| {
       if (upvals[j]) |u| L.allocator.destroy(u);
   }
   ```
   This frees `u`, but **never unlinks `u.gc` from the `g.allgc` linked list**.
3. If closure allocation fails at line 4167:
   ```zig
   if (upvals.len > 0 and upvals[0] != null) L.allocator.destroy(upvals[0].?);
   ```
   Only `upvals[0]` is destroyed (freeing memory while remaining linked in `g.allgc`). `upvals[1..]` are *not* destroyed either, but since they are registered in `g.allgc` they remain valid heap objects reachable by the sweep — the dangerous case is the unlinked, already-destroyed `upvals[0]`.
4. If `registerGC(L, cl)` fails at line 4174:
   `cl` itself is never freed (it is not yet registered), leaking the `lua_Closure` struct.

## Impact

When an allocation failure occurs while loading a prototype with upvalues:
- `g.allgc` retains a pointer to the deallocated `upvals[0]` heap block.
- On the next garbage collection cycle (`luaC_collectgarbage` or state close), the sweep phase dereferences the freed memory, leading to memory corruption, Use-After-Free (UAF), and Double-Free panics.
- Additionally, `cl` leaks when `registerGC(L, cl)` fails.

## Proposed Fix

1. Do not register upvalues in `g.allgc` before the closure is successfully constructed, or alternatively, unlink registered `uv.gc` nodes from `g.allgc` upon error cleanup.
2. In the closure failure blocks (lines 4167–4179), destroy `cl` when `registerGC(L, cl)` fails, and ensure the `upvals[0]` destroy path unlinks (or does not run before the list is cleaned) so no dangling `allgc` node remains.
