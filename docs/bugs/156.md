# BUG-156 — `coroutine.wrap` on a Dead Coroutine Raises "attempt to call a nil value"

- **Severity:** `MED`
- **Status:** ❌ OPEN
- **Location:** `src/lib/corolib.zig` (`wrap`/`auxwrap` implementation)
- **Upstream failure:** `lua/testes/coroutine.lua:69`

## Defect Summary

The reference `auxwrap` (`lua/lcorolib.c`) resolves the coroutine from the
wrapper's upvalue and calls `lua_resume`; a dead coroutine produces the
runtime error `"cannot resume dead coroutine"` (raised through the resume
status), which `wrap` then re-raises:

```lua
local co = coroutine.wrap(function () return "a" end)
co()                                  -- true, "a"
local ok, err = pcall(co)
-- C reference: ok == false, err == "cannot resume dead coroutine"
-- luazig:       ok == false, err == "attempt to call a nil value"
```

Verified directly (2026-09-08):

```
$ luazig -e 'local co=coroutine.wrap(function() return "a" end)
local ok,r=pcall(co); print("first:", ok, r)
local ok2,r2=pcall(co); print("second:", ok2, r2)'
first:  true  a
second: false attempt to call a nil value
```

## Impact

1. Any upstream test or user program pattern-matching the resume error message
   (e.g. `string.find(a, "dead")`, as `coroutine.lua:69` does) fails.
2. The `"attempt to call a nil value"` text indicates the wrap closure's
   coroutine reference is being lost/cleared once the thread reaches a dead
   state — i.e. the wrapper's internal state handling is wrong beyond just the
   message text.

## Proposed Fix

Port the reference `auxwrap` exactly (`lua/lcorolib.c:99-120`): keep the
thread in the wrapper's upvalue, check `lua_status`/resume return status, and
when the coroutine is dead/non-suspended raise
`luaG_runerror("cannot resume dead coroutine")` /
`"cannot resume non-suspended coroutine"` (messages already exist elsewhere in
the port — verify and reuse the exact strings).

## Evidence

- `cd lua/testes && ../../zig-out/bin/luazig coroutine.lua` → fails at line 69
  (`assert(not s and string.find(a, "dead") and coroutine.status(f) == "dead")`).
