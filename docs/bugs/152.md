# BUG-152 — Dead Code `checknoTM` and `Table.flags` Missing Invalidation on Key Mutation

- **Severity:** `LOW`
- **Status:** ✅ CLOSED
- **Location:** `src/ltm.zig:64-76` (`checknoTM`), `src/ltable.zig:213` (`Table.flags`), `src/lua.zig:3494`

## Defect Summary

1. In `src/ltm.zig:64-69`:
   ```zig
   pub inline fn checknoTM(mt: ?*lua.lua_Table, event: TMS) bool {
       if (mt) |m| {
           return (m.flags & (@as(u8, 1) << @intCast(@intFromEnum(event)))) != 0;
       }
       return true;
   }
   ```
   `checknoTM` is completely unused: grep confirms **zero call sites** anywhere in the project.
2. In `src/ltm.zig:71-80`:
   ```zig
   pub fn luaT_gettm(events: *lua.lua_Table, event: TMS, ename: *lua.lua_TString) ?lua.TValue {
       const tm = ltable.get(events, lua.TValue{ .string = ename });
       if (tm == .nil) {
           if (@intFromEnum(event) <= @intFromEnum(TMS.EQ)) {
               events.flags |= @as(u8, 1) << @intCast(@intFromEnum(event));
           }
           return null;
       }
       return tm;
   }
   ```
   `events.flags` records absence bits for metamethods, mirroring the Lua C `fasttm` macro. However, because no caller tests `flags`, this is purely write-only dead state.
3. Metamethod absence-cache invalidation is **partially implemented**. There is no named `invalidateTMcache` function, but `lua_setmetatable` does clear the cache (`src/lua.zig:3494`: `tbl.flags = 0`, mirroring `lua/lapi.c:933`). What is genuinely missing is invalidation on **key mutation**: the C reference clears the cache in `lua/ltable.c:1111` (`luaH_finishset`) and `lua/lvm.c:347` (insertion into the `__index` chain), but luazig's `ltable.set`/`setHash`/`setInt` never touch `flags`. If `checknoTM` were ever wired up, assigning a metamethod via a plain `t.__newindex = f` (rather than `setmetatable`) on an already-queried table would never take effect because the absence bit would stay cached indefinitely.

## Impact

- Clutters the code with dead functions and write-only field manipulations.
- Latent semantic bug if `fasttm` / `checknoTM` is ever activated without invalidation.
- Metamethod lookups always perform a hash lookup even when metamethods are known absent (lost performance optimization).

## Proposed Fix

Either:
1. Complete the `fasttm` optimization: wire `checknoTM` into metamethod lookups, and add cache invalidation (the counterpart of `ltable.c:1111` / `lvm.c:347`) in `ltable.set`/`setHash`/`setInt` whenever table keys are mutated. (`lua_setmetatable` invalidation already exists at `lua.zig:3494`.)
2. Or remove `checknoTM` and `events.flags` to eliminate dead code and state until ready to be implemented properly.

## Resolution

- Completed Option 1:
  - Updated `checknoTM` in `src/ltm.zig` to check `event <= TMS.EQ` before indexing into `m.flags` bitmask.
  - Added `fasttm` in `src/ltm.zig` and wired `checknoTM` into `luaT_gettmbyobj` to fast-path absence of cached tagmethods without performing table hash lookups.
  - Added `invalidateTMcache(t)` in `src/ltable.zig` (`t.flags = 0`) and called it on table mutation paths (`set`, `setHash`, `setInt`).
- Added unit test in `tests/test_basic.zig` verifying that absence is cached and mutating metatables (via plain `mt.__index = fn` and `mt.__newindex = fn`) invalidates the cache so updated metamethods immediately take effect.
