# BUG-128 — `lcode.zig`: swallowed OOM in `luaK_code*` emitters emits PC 0

- **Severity:** [HIGH]
- **Status:** ⏳ OPEN

- **Location:** `src/lcode.zig:263-312` — `luaK_codeABCk`, `luaK_codevABCk`,
  `luaK_codeABx`, `codeAsBx`, `codesJ`, `codeextraarg`.
- **Defect:** Each emitter wraps `luaK_code(...) catch { _ =
  llex.luaX_syntaxerror(fs.ls, "out of memory") catch {}; return 0; }`.
  `luaX_syntaxerror` merely *returns* an error value (`src/llex.zig:549-551`);
  discarding it with `catch {}` aborts nothing. Compilation then continues using
  the bogus instruction index 0 as if emission succeeded. This is exactly the
  defect class recorded as FIXED in BUG-093 ("constant allocation error fallback
  `catch 0` emits corrupt code"), BUG-094 and BUG-108 — the pattern is present
  again (or was never fully removed) in the current tree. §0.1 rule 2/12
  violation; the C reference unwinds compilation via `luaM_error`.
- **Impact:** Under memory pressure the compiler silently produces a malformed
  `lua_Proto` (jump patches referencing slot 0, wrong line info) instead of
  failing compilation; downstream failures are far from the root cause.
- **Proposed fix:** Make the emitters propagate (`try`) and let the parser-level
  error boundary convert OOM into a load failure; add a fault-injection test
  guarding against reintroduction.
