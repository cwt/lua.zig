# BUG-117 — `ldump.zig` / `lundump.zig`: dump wire format incompatible with Lua 5.5.1

- **Severity:** [HIGH]
- **Status:** ✅ FIXED

- **Location:** `src/ldump.zig:77-79` (`dumpInt` → `dumpInteger` zigzag) vs
  `lua/ldump.c:110-113` (`dumpInt` = plain `dumpVarint(cast_uint(x))`);
  counterpart loader deviation in `src/lundump.zig:100-103` (see BUG-116).
- **Defect:** Counts (`sizecode`, `sizek`, `sizep`, line numbers, debug counts)
  are emitted zigzag-encoded instead of as plain varints. Verified
  differentially: the reference binary rejects a port-produced dump with
  `bad binary format (invalid constant)`, and the port fails on
  reference-produced dumps with `truncated chunk`. Varint byte order itself is
  correct (port matches C's MSB-first encoder); the sole wire divergence is the
  count codec.
- **Impact:** Precompiled chunks are not interchangeable with Lua 5.5.1 — a
  hard drop-in-replacement failure for any build/packaging pipeline using
  `luac`-style artifacts. Port↔port round-trip functions only because writer
  and reader were changed symmetrically (which is itself the BUG-116 bug).
- **Proposed fix:** Make `dumpInt` emit plain varints and `loadInt` read plain
  varints (matching C), keeping zigzag strictly for `lua_Integer` constants;
  add a round-trip test against a reference-dumped fixture.
- **Fix:** Fixed `dumpInt` in `src/ldump.zig` to emit plain varints (`self.dumpVarint(@as(u64, @intCast(x)))`). Added round-trip unit test in `tests/test_basic.zig`.
