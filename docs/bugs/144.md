# BUG-144 — I/O Library Defects: Empty-Line Read Truncation, `read(0)` Unconditional Nil, `f:lines()` Non-Iterator, and FD Leaks

- **Severity:** `HIGH`
- **Status:** ⏳ OPEN
- **Location:** `src/lib/iolib.zig`
  - `read_line` (lines 389–402)
  - `read_chars` (lines 351–368)
  - `flib` registration (line 784)
  - `io_lines` / `f_lines` (lines 712–742)
  - `io_popen` (lines 275–291)

## Defect Summary

A cluster of functional and resource defects exists in `src/lib/iolib.zig`:

1. **Empty Line Premature EOF in `read_line`:**
   ```zig
   while (true) {
       const c = read_byte(p) orelse break;
       if (c == '\n') break;
       buf.append(L_.allocator, c) catch break;
   }
   if (buf.items.len > 0) {
       _ = lua.lua_pushlstring(L_, buf.items, buf.items.len);
       return true;
   }
   return false;
   ```
   When reading an empty line (`"\n"`), `buf.items.len` is `0`. The function returns `false`, causing `f:read("*l")` to push `nil` instead of the empty string `""`.

2. **`f:read(0)` Unconditionally Returns Nil:**
   In `read_chars`, when `n == 0`, `got == 0` evaluates to true:
   ```zig
   if (got == 0) return false;
   ```
   Per Lua 5.5.1 semantics, `read(0)` is an EOF probe: it must return `""` if there is still unread data or not at EOF, and `nil` only if at EOF. In `luazig`, it returns `nil` unconditionally.

3. **`f:lines()` Method Returns String Instead of Iterator:**
   In `flib` (line 784):
   ```zig
   .{ .name = "lines", .func = f_lines },
   ```
   Calling `for line in f:lines() do` calls `f_lines(f)`, which reads one line and returns a string. Lua then errors with `"attempt to call a string value"`. `f:lines()` must return an iterator function.

4. **File Descriptor Leak in `io.lines(filename)`:**
   When `io.lines(filename)` is used, reaching EOF in `f_lines` returns `0` without closing the file handle `p`. The file descriptor leaks until GC sweeps the object.

5. **Pipe FD and Zombie Child Leak in `io.popen`:**
   If `newfile(L_)` fails on line 282, `pipe_fd` is not closed and `child` is never waited or reaped, causing a file descriptor leak and an orphaned zombie process.

## Impact

Scripts performing standard file I/O experience truncated file reads, broken `for ... in f:lines()` loops, faulty EOF probing, file descriptor leaks (`EMFILE`), and zombie processes.

## Proposed Fix

1. In `read_line`, track whether any character (such as `'\n'`) was read, returning `""` when an empty line is read.
2. In `read_chars`, handle `n == 0` by probing for EOF via `read_byte(p)` (restoring the byte to `p.unget`).
3. Make `f:lines()` return an iterator closure over `self`.
4. In `f_lines`, close temporary files created by `io.lines` on EOF.
5. In `io_popen`, wrap child and `pipe_fd` in `errdefer` to kill/wait the child and close `pipe_fd` on failure.
