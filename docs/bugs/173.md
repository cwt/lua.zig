# BUG-173 — Ephemeron Convergence Loop Missing

- **Severity:** `HIGH`
- **Status:** ❌ OPEN
- **Location:** `src/lua.zig` (weak-table sweep, step 4.5), reference
  `lua/lgc.c` (`convergeephemerons`, `traverseephemeron`).
- **Upstream failure:** `lua/testes/gc.lua:322-357` ("ephemerons" section and
  the following `K` torture test).

## Defect Summary

In the C reference, weak-KEY tables are *ephemerons*: when a value stored in
an ephemeron table references one of its own (or another ephemeron's) keys,
the collector must iterate to a fixpoint (`convergeephemerons`) before
deciding which keys are dead. The port clears weak tables in a single pass,
so entries whose keys are only reachable *through other weak tables' values*
are cleared prematurely (or the traversal order destabilizes).

gc.lua exercises exactly this:

```lua
local mt = {__mode = 'k'}
a = {{10},{20},{30},{40}}; setmetatable(a, mt)
x = nil
for i = 1, 100 do local n = {}; a[n] = {k = {x}}; x = n end
GC()
local n = x
local i = 0
while n do n = a[n].k[1]; i = i + 1 end
assert(i == 100)      -- the whole list must survive via value->key chains
```

Standalone, luazig fails/segfaults in this section (reached after
[BUG-172](172.md) fixed the earlier weak-table defects).

## Impact

- `lua/testes/gc.lua` standalone fails in the ephemerons section.
- Programs using weak-key tables to build auxiliary indexes whose keys are
  reachable only through other weak structures lose entries prematurely.

## Proposed Fix

Port the reference's ephemeron convergence: during the mark phase, link
weak-key tables with white keys into an `ephemeron` list and iterate
`traverseephemeron` until no new values are marked; only then run the
clearing pass (`clearbykeys`). Alternatively, loop the port's
traverse+clear cycle to a fixpoint for weak-key tables before the sweep.

## Evidence

```
$ luazig lua/testes/gc.lua
...
weak tables
(segfault in the ephemerons section, after BUG-172's fix made line 249 pass)
```
