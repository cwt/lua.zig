# BUG-147 — `dofile` and `loadfile` Error on Omitted Filename Instead of Reading from `stdin`

- **Severity:** `MED`
- **Status:** ✅ FIXED
- **Location:** `src/lib/baselib.zig:197` (`dofile`) and `src/lib/baselib.zig:275` (`loadfile`)

## Defect Summary

In `src/lib/baselib.zig`:
```zig
fn dofile(L: *lua.lua_State) anyerror!i32 {
    const filename = try lauxlib.luaL_checklstring(L, 1, null);
    ...
```
and:
```zig
fn loadfile(L: *lua.lua_State) anyerror!i32 {
    const filename = try lauxlib.luaL_checklstring(L, 1, null);
    ...
```

Both functions use `luaL_checklstring` on argument 1.
According to the Lua Reference Manual:
- `dofile ([filename])`: Opens the named file and executes its contents as a Lua chunk. When called without arguments, `dofile` executes the contents of the standard input (`stdin`).
- `loadfile ([filename [, mode [, env]]])`: Similar to `load`, but gets the chunk from file `filename` or from the standard input, if no file name is given.

## Impact

Calling `dofile()` or `loadfile()` without arguments raises runtime error:
`"bad argument #1 to 'dofile' (string expected, got no value)"`
breaking standard Lua scripts and REPL-driven pipelines that pipe code into `dofile()`.

## Proposed Fix

Use `luaL_optlstring` (or check `lua_isnoneornil(L, 1)`):
If `filename == null`, read the chunk from `L.l_G.?.io` (`stdin`) instead of calling `readFileAlloc`.
