# BUG-179 — `LUA_EXTRASPACE` not ported

- **Severity:** `LOW` — only affects C extensions that use the
  `LUA_EXTRASPACE` / `lua_extrafield` embedding idiom; no in-tree or
  upstream-suite impact.
- **Status:** ✅ CLOSED
- **Location:** `src/lua.zig` (`lua_State` layout), `src/luaconf.zig`
  (constant).

## Defect Summary

`lua/luaconf.h` defines `LUA_EXTRASPACE` (in bytes) and the reference
`lua_State` is allocated with that many extra leading bytes. `luazig`'s
`lua_State` has no such reserved region and sets `LUA_EXTRASPACE = @sizeOf(void)` (0 bytes).

## Impact

- Any C host that embeds a pointer/state in the bytes before the
  `lua_State` will have it clobbered or misaligned.
- Cosmetic / edge-case conformance gap; not exercised by the upstream
  suite.

## Proposed Fix

Either add a `LUA_EXTRASPACE` constant + reserved leading bytes to
`lua_State` (matching the reference allocation), or document that luazig
does not support the `LUA_EXTRASPACE` idiom.

## Resolution

- Updated `LUA_EXTRASPACE` in `src/luaconf.zig` from `@sizeOf(void)` (0) to `@sizeOf(?*anyopaque)` (8), matching Lua 5.5.1 `luaconf.h` (`sizeof(void *)`).
- Defined wrapper `LX` struct in `src/lua.zig` containing `extra_: [luaconf.LUA_EXTRASPACE]u8` followed by `l: lua_State`, with compile-time assertion ensuring zero padding (`@offsetOf(LX, "l") == luaconf.LUA_EXTRASPACE`).
- Added `has_extraspace: bool` to `lua_State`.
- Implemented `lua_getextraspace(L: *lua_State) *anyopaque` resolving `extra_` via `@fieldParentPtr("l", L)` in `src/lua.zig`. (Because `LX` is a non-extern struct containing slices and optionals, Zig optimizes its field layout and reorders `l` to offset 0 and `extra_` after `l`; using `@fieldParentPtr` avoids corrupting the allocator chunk header that raw `L - LUA_EXTRASPACE` arithmetic caused).
- Exported C-ABI entry point `lua_getextraspace` in `src/lstate.zig`.
- Updated `c_luaL_newstate()` to allocate `lua.LX` on heap and mark `has_extraspace = true`.
- Updated `lua_newthread(L)` to allocate `lua.LX` for new threads, mark `has_extraspace = true`, and inherit parent's extraspace via `@memcpy` if parent has extraspace.
- Updated `lua_close` and `lgc.zig:freeGCObject` to safely free `LX` via `@fieldParentPtr("l", L)` when `has_extraspace` is set.
- Added unit test in `tests/test_basic.zig` verifying `LUA_EXTRASPACE` size, write/read roundtrip via `lua_getextraspace`, thread inheritance, and isolated thread modification.
