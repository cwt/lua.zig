# BUG-162 — `luaV_finishOp` Lacks Comparison/CONCAT Completion Cases

- **Severity:** `HIGH`
- **Status:** ❌ OPEN
- **Location:** `src/lvm.zig:535-570` (`luaV_finishOp`)
- **Reference:** `lua/lvm.c` `finishOp` (comparison + concat cases, ~1053-1096)

## Defect Summary

When a metamethod invoked by the VM yields (suspend), the pending instruction
must be *completed* on resume via `luaV_finishOp`. The C reference
`finishOp` (`lua/lvm.c`) handles, among others:

- `OP_LT`, `OP_LE`, `OP_LTI`, `OP_LEI`, `OP_GTI`, `OP_GEI`, `OP_EQ` — pop the
  result of the comparison metamethod and apply the conditional jump
  (`docondjump`) or the skip.
- `OP_CONCAT` — finish a yielded `__concat` by re-running `luaV_concat` with
  the preserved register range.

The port's `luaV_finishOp` (src/lvm.zig:535-570) implements only:
`MMBIN*`, `UNM`, `BNOT`, `LEN`, `GETTABUP`, `GETTABLE`, `GETI`, `GETFIELD`,
`SELF`, `CLOSE`, `RETURN`. The comparison and concat cases are absent.

## Impact

If a `__lt`/`__le`/`__eq`/`__concat` metamethod yields inside a coroutine:

- **Comparison:** the pending conditional jump is never applied on resume —
  control flow silently diverges (the jump decision is lost).
- **Concat:** the concat operand range is never re-run — garbage/missing
  result values.

Both are supported Lua patterns (`coroutine` tests exercise yields inside
metamethods; `big.lua` covers the metamethod-yield family — see also
[BUG-160](160.md)).

## Proposed Fix

Port the missing `finishOp` cases verbatim from `lua/lvm.c`:

```c
vmcase(OP_LT) ... OP_LE ... OP_LTI/LEI/GTI/GEI:  /* pop result, docondjump */
vmcase(OP_CONCAT):  /* re-run luaV_concat(L, GETARG_B(i)) preserving base */
```

The port already stores the resumption instruction in the CallInfo; only the
missing opcode branches need porting (the existing MMBIN case in the port
shows the frame-access pattern to follow).
