# BUG-162 — `luaV_finishOp` Lacks Comparison/CONCAT Completion Cases

- **Severity:** `HIGH`
- **Status:** ✅ RESOLVED
- **Location:** `src/lvm.zig:535-570` (`luaV_finishOp`), `src/lua.zig` (`CallInfo.concat_k`, `luaV_concat`)
- **Reference:** `lua/lvm.c` `finishOp` (comparison + concat cases, ~1053-1096)

## Defect Summary

When a metamethod invoked by the VM yields (suspend), the pending instruction
must be *completed* on resume via `luaV_finishOp`. The C reference
`finishOp` (`lua/lvm.c`) handles, among others:

- `OP_LT`, `OP_LE`, `OP_LTI`, `OP_LEI`, `OP_GTI`, `OP_GEI`, `OP_EQ` — pop the
  result of the comparison metamethod and apply the conditional jump
  (`docondjump`) or the skip.
- `OP_CONCAT` — finish a yielded `__concat` by re-running `luaV_concat` with
  the preserved register range.

The port's `luaV_finishOp` (src/lvm.zig:535-570) implemented only:
`MMBIN*`, `UNM`, `BNOT`, `LEN`, `GETTABUP`, `GETTABLE`, `GETI`, `GETFIELD`,
`SELF`, `CLOSE`, `RETURN`. The comparison and concat cases were absent.

## Impact

If a `__lt`/`__le`/`__eq`/`__concat` metamethod yielded inside a coroutine:

- **Comparison:** the pending conditional jump was never applied on resume —
  control flow silently diverged (the jump decision was lost).
- **Concat:** the concat operand range was never re-run — garbage/missing
  result values.

## Proposed Fix

Port the missing `finishOp` cases from `lua/lvm.c`:

```c
vmcase(OP_LT) ... OP_LE ... OP_LTI/LEI/GTI/GEI:  /* pop result, docondjump */
vmcase(OP_CONCAT):  /* re-run luaV_concat(L, GETARG_B(i)) preserving base */
```

## Resolution

1. **Comparison opcodes in `finishOp` (`src/lvm.zig`):**
   Added cases for `.LT, .LE, .LTI, .LEI, .GTI, .GEI, .EQ`:
   Pops the metamethod result from the stack top. Compares against the expected
   boolean condition `k = GETARG_k(inst) != 0`. If `res != k`, skips the
   following `OP_JMP` instruction by incrementing `ci.savedpc += 1` (or lets
   the jump instruction execute on resume if `res == k`).

2. **`CONCAT` completion in `finishOp` (`src/lvm.zig` & `src/lua.zig`):**
   - Added `concat_k: usize = 0` to `CallInfo` in `src/lua.zig`.
   - In `luaV_concat`, recorded `ci.concat_k = k` before invoking `luaT_trybinTM`.
   - In `finishOp`, popped the metamethod result, placed it into `ra_idx + k - 2`,
     and continued with `luaV_concat(L, k - 1, ra_idx)` if `k - 1 >= 2`.
   - Updated `finishOp` signature to return `anyerror!void` and updated call
     sites in `unroll` and `do_resume` to safely propagate errors.

## Verification

- Added comprehensive integration test in `tests/test_basic.zig`:
  `BUG-162: luaV_finishOp completion for comparison and CONCAT yields`
  verifying `__lt`, `__eq`, and `__concat` metamethods yielding within coroutines.
- Verified all unit tests pass (`zig build test`).
- Verified upstream tests pass.
