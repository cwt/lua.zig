# BUG-145 — Closed File Handles Bypass State Check and Issue Syscalls with `fd = -1`

- **Severity:** `MED`
- **Status:** ⏳ OPEN
- **Location:** `src/lib/iolib.zig:31-34` (`tostream`), called in `f_read`, `f_write`, `f_seek`, `f_flush`, `f_setvbuf`

## Defect Summary

In `src/lib/iolib.zig`:
```zig
fn tostream(L_: *L, idx: i32) !*LStream {
    const p = try lauxlib.luaL_checkudata(L_, idx, LUA_FILEHANDLE);
    return @as(*LStream, @ptrCast(@alignCast(p)));
}
```

When a file is closed in Lua, `f_close` sets `p.closef = null` and `p.fd = -1`.
However, `tostream` only checks that the userdata is of type `LUA_FILEHANDLE`. It does not check whether `p.closef == null` or `p.fd < 0`.

By contrast, the reference C implementation (`tofile` in `liolib.c`) enforces:
```c
static luaL_Stream *tofile (lua_State *L) {
  luaL_Stream *p = ((luaL_Stream *)luaL_checkudata(L, 1, LUA_FILEHANDLE));
  if (l_isclosed(p))
    luaL_error(L, "attempt to use a closed file");
  lua_assert(p->f);
  return p;
}
```

## Impact

When Lua code invokes methods on a closed file handle:
- `f:read()` issues `std.posix.read(-1, ...)` which fails with `EBADF`, returning `nil` (silent EOF) instead of throwing `"attempt to use a closed file"`.
- `f:seek()` issues `lseek(-1, ...)` which fails with `EBADF`, returning `false` instead of throwing an error.
- `f:write()` and `f:setvbuf()` behave erratically rather than failing immediately.

## Proposed Fix

Add a check in `tostream` (or a helper `checkfile` / `tofile`):
```zig
fn tofile(L_: *L, idx: i32) !*LStream {
    const p = try tostream(L_, idx);
    if (p.closef == null or p.fd < 0) {
        return lauxlib.luaL_error(L_, "attempt to use a closed file");
    }
    return p;
}
```
