# BUG-161 — Process Crash in the "Chain of `coroutine.close`" Test (`cstack.lua`)

- **Severity:** `CRITICAL` (hard crash / core dump, not a Lua error)
- **Status:** ✅ RESOLVED
- **Location:** `src/lib/corolib.zig` (`coroutine.close`, `luaB_auxwrap`), `src/ltm.zig` (`luaD_call`), `src/lua.zig` (`lua_closethread`, `luaF_closeupval`, GC thread free, `precall`), `src/lvm.zig` (`OP_CLOSE`)
- **Upstream failure:** `lua/testes/cstack.lua` — the test aborts the process
  (core dump) after printing `chain of 'coroutine.close'`.

## Defect Summary

Observed (2026-09-08):

```
$ cd lua/testes && ../../zig-out/bin/luazig cstack.lua
final count:  98
chain of 'coroutine.close'
.timeout: the monitored command dumped core
```

The upstream test walks a long chain of coroutines and closes them, expecting
the interpreter to raise a *catchable* stack-overflow error (via
`LUAI_MAXCCALLS` / C-stack limit checks, cf. `luaD_growCI` /
`stackinuse` protection in `lua/ldo.c`) rather than exhausting the native
stack. The port's `coroutine.close` chain path has no (or an ineffective)
depth guard here, so native recursion runs off the end of the real stack and
the process is killed by the OS.

## Impact

1. A user program creating/closing deeply nested coroutine chains crashes the
   whole interpreter instead of raising a catchable Lua error.
2. All upstream test files that also recurse here (none currently, because
   cstack.lua is harness-skipped) would take the runner down with them.

## Proposed Fix

1. Port the depth protections from `lua/ldo.c`: enforce `LUAI_MAXCCALLS`
   (200) increments in `luaD_callnoyield`-equivalents and the "error in error
   handling" margin along the `coroutine.close` → `closethread` → `__close`
   metamethod → nested call chain.
2. Convert the native recursion (if any) in the close chain into an iterative
   walk or an error-checked recursion that raises `"C stack overflow"`.
3. Verify with `cstack.lua` run standalone: it must complete (or fail with a
   Lua error), never dump core.

## Resolution

1. **`nCcalls` inheritance & enforcement across thread boundaries:**
   - In `lua_closethread`: inherited `nCcalls` from calling thread (`L.nCcalls = if (from) |f| f.nCcalls else 0`).
   - In `luaD_call`: tracked `L.nCcalls += 1` with `defer L.nCcalls -= 1`, enforcing `llimits.LUAI_MAXCCALLS` and raising `"C stack overflow"` via `luaD_errerr` when exceeded.
2. **GC Thread Cleanup Fix (`luaF_closeupval`):**
   - Separated `luaF_closeupval` (closing only open upvalues) from `closeupvals` (which also executes `__close` metamethods).
   - In `freeGCObject` for `.thread`: replaced `closeupvals(th, 0, null)` with `luaF_closeupval(th, 0)` matching PUC-Rio C reference (`luaE_freethread`), eliminating use-after-free and crash during GC sweep/`lua_close`.
3. **Coroutine Stack & Error Transfer Alignment:**
   - In `lua_resume`: pushed `L.err_obj` onto `L.stack[L.top]` on unrecoverable runtime errors matching `luaD_seterrorobj(L, status, L->top.p)` in PUC-Rio C.
   - In `lua_closethread`: positioned the error object at `L.stack[1]` and set `L.top = 2`, preserving the error value across thread resets.
   - In `src/lib/corolib.zig` (`luaB_auxwrap`): added missing `lua.lua_xmove(co, L, 1)` following `lua_closethread(co, L)` to transfer the error object from the closed coroutine.
   - In `src/lvm.zig` (`OP_CLOSE`): removed erroneous stack zeroing that was corrupting outer scope registers and loop variables.
4. **Harness Integration:**
   - Removed `cstack.lua` from `STANDALONE_SKIP` in `run_testes.sh` so it executes by default with other standalone tests.

## Verification

- `cstack.lua` executes standalone and passes 100% (all subtests including "chain of 'coroutine.close'" print `OK`).
- All 167 Zig unit tests pass (`zig build test`).
- Full test runner (`./run_testes.sh`) reports **PASS: 20, FAIL: 0, CRASH: 0, TIMEOUT: 0**.
