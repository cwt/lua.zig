# BUG-154 — `std.process.exit` in `main` Bypasses `lua_close` and GPA `deinit` Defer Handlers

- **Severity:** `LOW`
- **Status:** ✅ CLOSED
- **Location:** `src/luazig.zig:514-516` (`main`)

## Defect Summary

In `src/luazig.zig`:
```zig
pub fn main(init: std.process.Init) !void {
    ...
    defer _ = dbg_alloc.deinit();
    ...
    const L = try gpa.create(lua.lua_State);
    defer gpa.destroy(L);
    try lua.luaL_newstate_io(L, gpa, io);
    defer lua.lua_close(L);
    ...
    if (had_error) {
        std.process.exit(1);
    }
}
```

`std.process.exit(1)` calls the OS `sys_exit` directly without unwinding the stack.
When an error occurs (`had_error == true`):
- `defer lua.lua_close(L)` is skipped.
- `defer gpa.destroy(L)` is skipped.
- `defer _ = dbg_alloc.deinit()` is skipped.

## Impact

1. Lua finalizers (`__gc`, `__close` on file handles and userdata) are never run when a script terminates with an error, skipping buffer flushes and file closes.
2. In debug or test builds (`build_options.debug_alloc` or ASAN), `dbg_alloc.deinit()` is never reached, preventing leak detection reports on error exit paths.

## Proposed Fix

Return an error from `main` or let `main` return `u8` status code so that Zig executes all scope defers before exiting.

## Resolution

- Changed `pub fn main(init: std.process.Init)` return type to `!u8` in `src/luazig.zig`.
- Replaced `std.process.exit(1)` calls with `had_error = true` and `return 1`, returning `0` on success.
- This guarantees all stack defers (`defer lua.lua_close(L)`, `defer gpa.destroy(L)`, `defer _ = dbg_alloc.deinit()`) execute cleanly on error exit paths before process exit.
- Added unit test in `tests/test_basic.zig` executing a failing script through the CLI binary and verifying exit code 1.
