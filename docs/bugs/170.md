# BUG-170 — `LUA_READLINELIB` (Lua 5.5.1) Readline Library Not Implemented

- **Severity:** `MED`
- **Status:** ✅ RESOLVED
- **Location:** `src/luazig.zig` (REPL driver), `src/luaconf.zig` (no
  `LUA_READLINELIB` default), reference `lua/lua.c` / `lua/luaconf.h`.
- **Upstream failure:** `lua/testes/main.lua:206`.

## Defect Summary

`main.lua` (run with `release >= "5.5.1"`) tests the new `LUA_READLINELIB`
feature:

```lua
local env = "LUA_READLINELIB=xuxu LUA_INIT=\"warn('@allow')\""
local code = 'echo " " | env %s lua %s -W -i >%s 2>&1'
RUN(code, env, "", out)
assert(string.find(getoutput(), "warning: unable to load readline library 'xuxu'"))
RUN(code, env, "-E", out)
assert(not string.find(getoutput(), "warning"))
```

The reference REPL tries to `dlopen` the library named by `LUA_READLINELIB`
(default `LUA_LIB_READLINE`), and if it cannot load it, emits the warning
`warning: unable to load readline library '<name>'` (suppressed under `-E`).
The port's CLI/REPL driver has no readline-library loading at all, so the
warning never appears and `main.lua:206` fails.

## Impact

- `lua/testes/main.lua` fails at line 206 when run standalone (after
  [BUG-165](165.md) is fixed, line 193 now passes). This also keeps `all.lua`
  from fully passing since it runs `main.lua`.
- The 5.5.1 readline library integration is absent.

## Context

This is a 5.5.1-specific feature layered on top of the `!`/`LUA_EXEC_DIR`
and `-E` machinery that [BUG-129](129.md) already handled. It is the immediate
next blocker on `main.lua` once the default-path defect (BUG-165) is cleared.

## Resolution

Three parts, mirroring the reference:

1. **Warning state machine** (`src/lauxlib.zig`, port of
   `lua/lauxlib.c:1085-1140`): `warnfon` (on, prefixes `"Lua warning: "`),
   `warnfoff` (off: only control messages processed), `warnfcont`
   (continuation), and `checkcontrol` handling `@off`/`@on` (unknown `@`
   messages ignored but still control). Installed as the default handler by
   `luaL_newstate_io` (the reference `luaL_newstate` does the same). The
   stand-alone driver sends `@off` at startup like the reference `runargs`,
   so `-W` re-enables warnings.
2. **`luaB_warn`** (`src/lib/baselib.zig`): now routes every argument through
   the warning machinery with the tocont continuation protocol (previously it
   wrote to stderr directly, bypassing `@off`/`@on` and the prefix).
3. **`lua_initreadline`** (`src/luazig.zig`, port of `lua/lua.c:515`): at
   REPL entry the driver loads the library named by `LUA_READLINELIB` (or the
   luaconf default `libreadline.so`) via `std.DynLib`, resolving `readline`;
   on failure it emits the reference three-part warning
   `unable to load readline library '<name>'`. `-E` (LUA_NOENV) makes the env
   var be ignored via `luaL_getenv`. The `readline`/`add_history` symbols are
   resolved but intentionally not wired into the line-based REPL (readline
   line-editing remains out of scope, cf. H.6).

## Verification

- `LUA_READLINELIB=xuxu luazig -W -i` → `Lua warning: unable to load readline
  library 'xuxu'` (the main.lua:206 first assertion).
- `LUA_READLINELIB=libreadline.so.8 luazig -W -i` → silent (a valid library
  loads without warning).
- With `-E` the env var is ignored (the warning, when the *default* library
  is missing, names `libreadline.so`). Note: on machines without the
  unversioned `libreadline.so` dev symlink the main.lua:211 `-E` assertion
  fails identically for the C reference — the assertion assumes the default
  library is installed.
- `lua/testes/main.lua` now proceeds past line 206 (fails at line 211 on this
  machine only for the environmental reason above).
- New unit tests in `tests/test_basic.zig`: the warning state machine
  (`@off`/`@on`/unknown-control/tocont transitions) and a CLI subprocess test
  for the `xuxu` warning.
- `zig build test` → all tests passing, 0 leaks. `./run_testes.sh` → 20 PASS / 0
  FAIL / 0 CRASH.
