# BUG-178 — Missing auxlib: `luaL_checkunsigned` / `luaL_optunsigned` / `luaL_opt` / `luaL_getmetatable`

- **Severity:** `MED` — API-surface gap for C embedding consumers.
- **Status:** ✅ CLOSED
- **Location:** `src/lauxlib.zig`.

## Defect Summary

`lua/lauxlib.h` declares `luaL_checkunsigned`, `luaL_optunsigned` (new in
5.5), a generic `luaL_opt(L, n, def, t)` (macro over `luaL_optlstring` /
`luaL_optinteger` / `luaL_optnumber`), and `luaL_getmetatable`. `luazig`
has the typed variants (`checkstring` / `checklstring` / `checknumber` /
`checkinteger` / `optstring` / `optlstring` / `optnumber` / `optinteger`)
but not the unsigned pair, the generic `luaL_opt`, or
`luaL_getmetatable`.

## Impact

- C extension code that uses `luaL_checkunsigned` (validating a
  `lua_Unsigned` argument) or a generic `luaL_opt` for a type-matched
  default has no working equivalent.
- `luaL_getmetatable` is the canonical way to fetch a metatable from the
  registry by name; its absence forces manual `luaL_getsubtable` +
  `luaL_checktype` sequences.

## Proposed Fix

Add `luaL_checkunsigned` / `luaL_optunsigned` (delegating to the integer
checker with a non-negativity guard), a generic `luaL_opt`, and
`luaL_getmetatable` to `src/lauxlib.zig`, matching the reference
signatures.

## Resolution

- Implemented `luaL_checkunsigned` and `luaL_optunsigned` in `src/lauxlib.zig` delegating to `luaL_checkinteger` / `luaL_optinteger` with two's-complement bitcast to `lua_Unsigned`.
- Implemented generic comptime `luaL_opt(L, func, idx, def)` in `src/lauxlib.zig`, returning default if none or nil, otherwise executing `func(L, idx)` and propagating errors if an error union is returned.
- Implemented `luaL_getmetatable(L, tname)` in `src/lauxlib.zig` fetching from `LUA_REGISTRYINDEX`.
- Re-exported all four functions in `src/lua.zig`.
- Added unit test in `tests/test_basic.zig` exercising positive, negative, and invalid arguments, optional defaults, metatable retrieval, and generic opt fallbacks.
