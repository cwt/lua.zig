# BUG-131 — minor output-text divergences (`string.rep` message, `%p` padding)

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `src/lib/stringlib.zig` (`string.rep` size-guard error text);
  pointer formatting in the `tostring`/`luaL_tolstring` fallback for tables,
  functions, threads and userdata (compare C `lua/lstrlib.c` `%p`-based path).
- **Defect:**
  1. `pcall(string.rep, "x", math.maxinteger)` returns `"error"`; the reference
     returns `"resulting string too large"` (differential-confirmed).
  2. `tostring({})` renders `table: 0x0000001cddc7f0` (fixed-width zero padding);
     reference renders `table: 0x26654ee0` (differential-confirmed). Same for
     function/thread/userdata pointers.
- **Impact:** Test suites that match error strings or output formats fail;
  cosmetic otherwise.
- **Proposed fix:** Copy the reference's exact message constants and format
  pointers with plain `{x}` (no width specifier).
