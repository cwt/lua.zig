# BUG-148 — `math.random(n)` Missing Lower Bounds Check on Single-Argument Calls

- **Severity:** `MED`
- **Status:** ✅ FIXED
- **Location:** `src/lib/mathlib.zig:306-314` (`math_random`)

## Defect Summary

In `src/lib/mathlib.zig`:
```zig
} else if (nargs == 1) {
    const up = try lauxlib.luaL_checkinteger(L, 1);
    if (up == 0) {
        lua.lua_pushinteger(L, @as(i64, @bitCast(rv)));
        return 1;
    }
    const p = project(rv, @as(u64, @bitCast(up -% 1)), state);
    lua.lua_pushinteger(L, @as(i64, @bitCast(p)) + 1);
    return 1;
```

In Lua, `math.random(n)` for $n \neq 0$ is specified as generating an integer in the interval $[1, n]$. If $n < 1$ (e.g. `math.random(-5)`), the interval $[1, -5]$ is empty, and Lua must raise `"bad argument #1 to 'random' (interval is empty)"`.

In `luazig`:
- `nargs == 2` has the check:
  ```zig
  try lauxlib.luaL_argcheck(L, low <= up, 1, "interval is empty");
  ```
- But `nargs == 1` completely omits checking `up >= 1`. If `up < 0`, `up -% 1` wraps to a huge positive integer, and `math.random` returns arbitrary large positive numbers instead of raising an error.

## Impact

Violates the Lua 5.5.1 specification and hides caller bugs where invalid non-positive bounds are passed to `math.random`.

## Proposed Fix

Add `try lauxlib.luaL_argcheck(L, up >= 1, 1, "interval is empty");` in the `nargs == 1` branch when `up != 0`.
