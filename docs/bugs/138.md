# BUG-138 — Misc library/API divergences (differential-testing cluster)

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location / items:**
  - `src/lib/iolib.zig:250-253` (`io_popen`): read-mode pipes set the child's
    stdin to `.ignore`; POSIX `popen("r")` inherits the parent's stdin. Programs
    like `io.popen("read x; echo $x")` see EOF instead of terminal input.
  - `src/lib/iolib.zig:297-317` (`io_tmpfile`): single `openat(..., .EXCL)`
    attempt with no retry loop on name collision; C's `luaO_tmpfilename`
    retries (`os.tmpname` semantics).
  - `src/lua.zig:5816-5825` (`luaL_dostring`): maps every `lua_pcallk` failure to
    `LUA_ERRRUN` (except Yield), losing `LUA_ERRMEM`/`LUA_ERRERR` distinctions;
    also drops the underlying Zig error entirely.
  - `src/lua.zig:1486-1495` (`lua_xmove`): silently copies fewer values when `n`
    exceeds either side's availability; C asserts/raises ("invalid use of
    lua_xmove"-class errors) instead of corrupting stack discipline.
- **Impact:** Each item is an observable divergence from Lua 5.5.1 reachable from
  ordinary code or embedding use.
- **Proposed fix:** Inherit stdin for read-popen; retry tmpfile names; map pcallk
  error tags faithfully; make xmove raise a Lua error on mismatch like the
  reference's `api_incr_top`/assert path.
