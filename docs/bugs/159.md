# BUG-159 — `io.stdin:seek("set", 1000)` Does Not Return `(nil, message, code)` on Invalid Seek

- **Severity:** `MED`
- **Status:** ✅ RESOLVED
- **Location:** `src/lib/iolib.zig` (`f_seek` implementation)
- **Upstream failure:** `lua/testes/files.lua:88`

## Defect Summary

Upstream `files.lua:86-89`:

```lua
if not _port then   -- invalid seek
  local status, msg, code = io.stdin:seek("set", 1000)
  assert(not status and type(msg) == "string" and type(code) == "number")
end
```

The reference `f_seek` (`lua/liolib.c`) calls `fseek`/`lseek` and, on failure,
returns `nil`, the error message, and the numeric error code (whence/errno via
`luai_...`/`errno` mapping). The port's seek implementation does not produce
this three-value failure shape for an invalid seek on stdin.

## Impact

- `lua/testes/files.lua` fails at line 88 when run standalone.
- User code pattern-matching seek failures (`if not status then ... end`) gets
  the wrong result shape (nil or an error throw instead of `nil, msg, code`).

## Resolution

Ported `f_seek` to the reference (`lua/liolib.c`):

1. **`whence` validation** — replaced the silent `lua_tostring` fallback
   (which coerced any non-string to `"cur"`) with
   `luaL_checkoption(L, 2, "cur", {"set","cur","end"})`, so an invalid
   `whence` raises the reference `"bad argument #2 to 'seek' (invalid
   option)"` error instead of being ignored.
2. **Offset** — `luaL_optinteger(L, 3, 0)` instead of
   `lua_tointeger`-coerce-to-default.
3. **Failure shape** — on `lseek` failure the function now returns the
   reference three-value result `(nil, message, errno)` via
   `luaL_fileresult(L, false, null, errno)` (errno captured after clearing it
   pre-syscall, mirroring the C `errno = 0;` before `fseek`). Previously it
   pushed a bare `false`.
4. **`strerrorName` gap** — added `29 => "Illegal seek"` (ESPIPE), the errno
   produced by seeking a pipe/`stdin`, so the failure message is meaningful
   rather than the `"error"` default.

## Verification

- `io.popen(...):seek("set", 0)` (a non-seekable pipe) returns
  `(nil, "Illegal seek", 29)`; a valid seek on `/dev/null` returns the new
  position; an invalid `whence` raises.
- New unit test `BUG-159: f_seek returns (nil, message, code) on invalid seek
  and validates whence` in `tests/test_basic.zig`.
- `./run_testes.sh` → 20 PASS / 0 FAIL / 0 CRASH (files.lua is on the
  standalone skip list for unrelated harness deps; the seek block is verified
  directly).
