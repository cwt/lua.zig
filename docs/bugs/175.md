# BUG-175 — `luaL_openselectedlibs` preload omission + `LUA_*LIBK` bitmask alignment

- **Severity:** `MED` — API-surface gap: no functional bug in the shipped
  interpreter, but a C or Zig embedding consumer cannot express "preload only
  these libraries" into `package.preload` or use standard bitmasks.
- **Status:** ✅ FIXED
- **Location:** `src/lualib.zig` (openers), `src/lauxlib.zig:1045`
  (`luaL_openselectedlibs`), `src/lua.zig:873` (divergent `LUA_*LIB` masks).

## Defect Summary

The reference ships `luaL_openselectedlibs(L, load, preload)` (`lua/linit.c`)
plus the bitmask constants `LUA_GLIBK`…`LUA_UTF8LIBK` and the macros
`LUA_NOLIB` / `LUA_ALL_LIBS` (`lua/lualib.h`). While `luazig` defines
`luaL_openselectedlibs` at `src/lauxlib.zig:1045`, it ignored `closedmask`
(`_ = closedmask;`), leaving preloading into `package.preload` unimplemented.
Furthermore, the bitmask constants in `src/lua.zig:873-884` used different bit
shifts and names (`LUA_BASELIB`, `LUA_COLIB`, etc.) rather than matching the
reference `LUA_*LIBK` constants.

## Resolution

1. Defined `LUA_GLIBK`…`LUA_UTF8LIBK` (and `LUA_BITLIBK`), `LUA_NOLIB`, and `LUA_ALL_LIBS` in `src/lua.zig` matching Lua 5.5.1 `lualib.h`, retaining backward-compatible aliases for `LUA_BASELIB` etc.
2. Implemented `luaopen_*` functions and the `stdlibs` array in `src/lualib.zig`.
3. Updated `luaL_openselectedlibs` in `src/lauxlib.zig` to populate `package.preload` when `closedmask & lib.mask != 0`, and load eagerly via `luaL_requiref` when `openmask & lib.mask != 0`.
4. Verified with unit test `BUG-175: luaL_openselectedlibs preload and bitmasks` in `tests/test_basic.zig`.
