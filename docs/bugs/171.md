# BUG-171 — Local Self-Reference Through a Closure Reads the Pre-Assignment Value

- **Severity:** `HIGH`
- **Status:** ❌ OPEN
- **Location:** `src/lparser.zig` (upvalue creation / register→upvalue
  promotion) and/or `src/lvm.zig` (`OP_GETUPVAL` / upvalue setup in
  `pushclosure`), reference `lua/lparser.c` (`luaK_...` upvalue handling) and
  `lua/lfunc.c` (`luaF_captureupval`).
- **Discovered while:** verifying [BUG-168](168.md) (the close-while-closing
  pattern `local co = coroutine.create(function() ... coroutine.close(co) end)`
  reads `co` as `nil` inside the closure).

## Defect Summary

```lua
local holder
holder = (function()
  local h = { get = function() return holder end }
  return h
end)
print(holder.get())   -- C reference: the table `h`; luazig: nil (or the
                      -- function, i.e. the pre-assignment value of `holder`)
```

And the close case:

```lua
local co = coroutine.create(function ()
  local x <close> = setmetatable({}, {__close = function()
    coroutine.close(co)   -- C reference: co is the thread; luazig: nil
  end})
  coroutine.yield(20)
end)
```

In the C reference, a local referenced by an inner closure is promoted to an
upvalue that shares its cell with the outer scope, so the closure always sees
the *current* value (including after `co = coroutine.create(...)` assigns it).
The port's closure captures a snapshot of the value as of closure creation
(pre-assignment `nil`), so the self-reference is wrong.

Note the workaround: `local co; co = coroutine.create(...)` (separate
declaration and assignment) behaves correctly, which is the form the upstream
`coroutine.lua:175` uses. The defect only manifests with the
*assigned-at-declaration* form (`local co = ...`).

## Impact

- User code that self-references a local through a closure created in the
  same `local` initializer (a common pattern, e.g. `local x = newThing(function() return x end)`)
  silently gets `nil` / the pre-assignment value.
- Observed as `coroutine.close(co1)` reporting `"bad argument #1 to 'close'
  (thread expected, got nil)"` when written as `local co1 =
  coroutine.create(...)`.

## Proposed Fix

In `lparser.zig`, when a local is referenced by an inner function and is
assigned in its own declaration (`local a = f(a-using-closure)`), the upvalue
must be a *shared* upvalue (an `UpVal` cell pointed to by the outer register),
not a captured value snapshot. Ensure `OP_GETUPVAL` reads the live cell and
`pushclosure`/`luaF_captureupval` bind the upvalue to the outer register.

## Evidence

```
$ luazig -e 'local co = coroutine.create(function() coroutine.close(co) end) ...'
bad argument #1 to 'close' (thread expected, got nil)
$ luazig -e 'local co; co = coroutine.create(function() coroutine.close(co) end) ...'
(succeeds)
```
