# BUG-171 — FALSE POSITIVE: Assigned-at-Declaration Self-Capture Is Correct

- **Severity:** `HIGH` (reported) — ❌ **FALSE POSITIVE**
- **Status:** ❌ FALSE POSITIVE (behavior matches the C reference)
- **Location:** n/a — `src/lparser.zig` / `src/lvm.zig` upvalue handling is
  correct.
- **Raised while:** writing the [BUG-168](168.md) test.

## Why the Report Was Wrong

The original report claimed that in

```lua
local co = coroutine.create(function ()
  coroutine.close(co)   -- luazig: co is nil -> "bad argument #1 (thread expected)"
end)
```

the inner closure should capture the new local `co`, and reading `nil` was an
upvalue bug. That contradicts Lua's visibility rules (Reference Manual §3.5,
Visibility Rules): **the scope of a local variable begins at the first
statement after its declaration**, so a name used inside the initializer
expression refers to the outer variable — here the *global* `co`, whose value
is nil. This is the classic documented gotcha (Programming in Lua §6.2:
"`local f = function (...) ... f ... end` — here the f inside the function
refers to the global f"); it is exactly why the `local function f` sugar
exists and why upstream `lua/testes/coroutine.lua:175` writes

```lua
local co
co = coroutine.create(...)
```

(the two-statement form puts the local in scope before the closure is
created, so the closure captures the local as an upvalue).

## Verification

```lua
f = "GLOBAL"
local g = function() return f end
print(g())                       -- "GLOBAL"  (inner f is the global)
local h; h = function() return h end
print(type(h()))                 -- "function" (inner h is the local upvalue)
local co = coroutine.create(function() return co end)
print(select(2, coroutine.resume(co)))  -- nil (inner co is the global co)
```

luazig produces all three reference results. The second repro in the original
report ("attempt to index a function value (local 'holder')") was a typo in
the repro script itself — `holder = (function() ... end)` missing the call
parentheses, so `holder` really held a function.

No code change needed.
