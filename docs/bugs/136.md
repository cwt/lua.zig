# BUG-136 — `getGCObject` linear-scan fallbacks beyond strings

- **Severity:** [LOW]
- **Status:** ✅ FIXED

- **Location:** `src/lua.zig:4510-4540` — per-type branches for `*lua_Table`,
  `*lua_Closure`, `*lua_Udata`, `*lua_Proto`, `*UpVal` were falling back to a full
  `allgc` walk when the cached back-pointer was null.
- **Defect:** Unregistered or early-inspected GC objects triggered O(allgc) linear scans
  on mark attempts, causing O(N²) degradation in allocation-heavy cycles.
- **Impact:** Latency spikes during `collectgarbage` in allocation-heavy workloads.
- **Proposed fix:** Make back-pointer lookups direct O(1) across all object types, deleting
  the fallback loops.
- **Fix:** Replaced linear-scan loops in `getGCObject` across all types (`*lua_Table`, `*lua_Closure`, `*lua_Udata`, `*lua_Proto`, `*UpVal`, `*lua_State`) with direct O(1) `.gc` back-pointer returns. Added unit test in `tests/test_basic.zig`.
