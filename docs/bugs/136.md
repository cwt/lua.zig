# BUG-136 — `getGCObject` linear-scan fallbacks beyond strings

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `src/lua.zig:4436-4511` — per-type branches for `*lua_Table`,
  `*lua_Closure`, `*lua_Udata`, `*lua_Proto`, `*UpVal` fall back to a full
  `allgc` walk when the cached back-pointer is null. The string branch was fixed
  by BUG-113 to avoid exactly this scan.
- **Defect:** Objects created without `registerGC` (or whose back-pointer is
  consulted before registration) force an O(allgc) lookup on every mark; with
  many such objects marking degenerates toward O(N²). The comment at 4491-4496
  documents the string case but the other five types retain the pattern.
- **Impact:** Latency spikes during `collectgarbage` in allocation-heavy
  workloads if any creation path skips registration; currently latent because
  audited paths register objects, which is also why it survives testing.
- **Proposed fix:** Make back-pointer assignment unconditional at every creation
  site (assert non-null instead of scanning), deleting the fallback loops.
