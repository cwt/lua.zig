# BUG-132 — `iolib.g_write`: `catch unreachable` on number formatting

- **Severity:** [LOW]
- **Status:** ✅ FIXED

- **Location:** `src/lib/iolib.zig:627` (integer branch) and `635` (float branch)
  of `g_write`.
- **Defect:** `std.fmt.bufPrint(&buf, "{d}", .{val}) catch unreachable`. The
  float case can legitimately fail: `{d}` expands large/small floats to hundreds
  of characters while the buffer is 64 bytes. §0.1 rule 2 explicitly forbids
  `catch unreachable` on fallible operations. (The formatting divergence itself
  is BUG-123.)
- **Impact:** Panic (Debug/ReleaseSafe) or UB (ReleaseFast) when writing such
  numbers via `file:write`; latent because the common float path is currently
  reached only for values whose expansion fits.
- **Proposed fix:** Propagate a write failure (`return luaL_fileresult(... false ...)`)
  or pre-size the buffer via the shared number formatter.
- **Fix:** Replaced separate branches and `catch unreachable` with unified `lua.luaO_tostringbuff(v, &buf)` with 128-byte buffer, eliminating `catch unreachable` and preventing buffer overflow panics on extreme numbers. Added unit test in `tests/test_basic.zig`.
