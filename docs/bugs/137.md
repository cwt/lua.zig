# BUG-137 — Dead code inventory (2026-08-24 audit)

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location / items:**
  - `src/libm.zig.orig` — committed editor backup file, tracked in the repo.
  - `src/lua.zig:5604` `lua_numbertocstring` — no callers anywhere (`rg` confirms);
    its float path also carries the BUG-123 `{d}` defect.
  - `src/lua.zig:5097` `hasFinalizer` — defined, never called (the pre-pass uses
    `rawHasFinalizer` directly).
  - `Table.lenhint` (`src/lua.zig:330`, set at `src/ltable.zig:218`) — written,
    never read.
  - `src/lua.zig:1135-1145` vs `1162-1172` — `registerGC` assigns object
    back-pointers twice with two identical switches; one block is redundant.
  - `src/lundump.zig:345-352` — `if (e == error.TruncatedChunk)` where both arms
    produce byte-identical messages (see BUG-116).
  - `src/lstring.zig:39-43` — stale doc-comment claiming the API string cache is
    consulted "including long strings"; the code path excludes them
    (`s.len <= LUAI_MAXSHORTLEN` guard at line 50), diverging from C's
    `luaS_new` which caches long strings too.
- **Impact:** No behavioral effect; misleads future audits (the stale comment in
  particular documents behavior that does not exist).
- **Proposed fix:** Delete the backup file and unused functions, drop `lenhint`,
  collapse the duplicate switch, unify the lundump message mapping, and correct
  the comment (or implement long-string caching like C).
