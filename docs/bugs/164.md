# BUG-164 — `debug.debug()` Is a Placeholder

- **Severity:** `LOW`
- **Status:** ❌ OPEN
- **Location:** `src/lib/debug.zig:465-470` (`db_debug`)
- **Reference:** `lua/ldblib.c:427-438` (`db_debug`)

## Defect Summary

The reference `debug.debug()` enters an interactive console: prints the
prompt, reads lines from stdin until a line consisting of `cont`, and runs
each line through `lua_dostring` in the caller's context (accumulating lines
for incomplete chunks).

The port prints `"lua_debug> compilation not supported in this port yet"` and
returns 0. It is a placeholder, not a port. It also writes that message with a
swallowed error (`catch {}`), a residual violation of §0.1 rule 12 (empty
catch blocks) — the systematic audit left this one site.

## Impact

- `debug.debug()` is unusable in the REPL-breakpoint workflow that upstream
  tests and interactive debugging sessions rely on.
- One remaining silent `catch {}` site in `src/`.

## Proposed Fix

1. Port `db_debug` from `lua/ldblib.c`: loop reading a line from `io`
   (threaded `std.Io`), stop on `"cont"`, `luaL_loadbuffer` + `lua_pcall`
   each line, accumulate incomplete chunks (syntax error containing
   `<eof>`), print errors to stderr.
2. Remove the swallowed-write `catch {}` (handle or propagate the write
   result).
