# BUG-157 — `package.searchpath` With `init=".", sep="."` Returns the Bare Name

- **Severity:** `MED`
- **Status:** ❌ OPEN
- **Location:** `src/lib/loadlib.zig` (`searchpath` name-conversion helper)
- **Upstream failure:** `lua/testes/attrib.lua:138`

## Defect Summary

The reference name conversion (`lua/loadlib.c`, `searchpath`/`gsub` step)
replaces every character of `name` that is in the `init` set with `sep`, but
skips the replacement when the character equals `sep` itself:

```c
for (; *name; name++) {
  if (strchr(init, *name) != NULL && *name != *sep)
    luaL_addchar(&b, *sep);
  else
    luaL_addchar(&b, *name);
}
```

The port's result differs in the `init == sep == "."` case:

```
$ cd lua/testes
$ luazig -e 'print(package.searchpath("C.lua", "libs/?", "", ""))'   -- line 137: OK
libs/C.lua
$ luazig -e 'print(package.searchpath("C.lua", "libs/?", ".", "."))' -- line 138: BAD
C.lua                ← expected: libs/C.lua
```

The port appears to mangle the template/name join when the separator
substitution is a no-op (init char == sep char), losing the `libs/` prefix —
the returned string is the bare name, not the template-expanded path.

## Impact

`package.searchpath` with explicit `init`/`sep` arguments (used heavily by
module loaders and `attrib.lua`) returns the wrong path, so found modules are
misreported (`require` chains built on searchpath break) and upstream test
`attrib.lua:138` fails while line 137 passes.

## Proposed Fix

Port the reference conversion loop verbatim (the `&& *name != *sep` guard is
the missing piece), and verify the three attrib.lua assertions:

```lua
package.searchpath("C.lua", D"?", "", "")   == D"C.lua"
package.searchpath("C.lua", D"?", ".", ".") == D"C.lua"
package.searchpath("--x-", D"?", "-", "X")  == D"XXxX"   -- already passes
```
