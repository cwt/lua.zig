# BUG-169 — `LUA_GCSTEP` Always Completes a Full Cycle

- **Severity:** `MED`
- **Status:** ✅ RESOLVED
- **Location:** `src/lua.zig` (`lua_gc` `LUA_GCSTEP` arm — "Run a full
  synchronous collection for each step request").
- **Upstream failure:** `lua/testes/gc.lua:71`.

## Defect Summary

`gc.lua` measures how many `collectgarbage("step", siz)` calls it takes to
finish a collection cycle and asserts that a bigger `siz` needs fewer steps
than a smaller one:

```lua
assert(dosteps(10) < dosteps(2))
```

The C reference runs a *portion* of the collector proportional to `siz` per
call and only signals cycle-complete when a full cycle has actually finished,
so `dosteps(10) < dosteps(2)`. The port (Phase H.10) runs a **full**
synchronous collection on every `LUA_GCSTEP` call, so `dosteps(n) == 1` for
every `n` and the strict inequality fails at `gc.lua:71`.

## Impact

- `lua/testes/gc.lua` fails at line 71 when run standalone (gc.lua is on the
  harness T/standalone skip list, so this does not surface in
  `./run_testes.sh`'s default run).
- `collectgarbage("step")` does much more work than the reference on each
  call (a full collection instead of a bounded slice), which is a real
  performance divergence, not just a test-cosmetic one.

## Context

This is the remaining conformance gap behind [BUG-158](158.md): BUG-158
fixed the *mode round-trip* return value (gc.lua:14-15) and is now closed;
this bug is the *step-size* semantics (gc.lua:71). A conformant fix requires
porting bounded incremental stepping (`luaC_condGC` / step-budget logic from
`lua/lgc.c`), which is larger scope than a single-line return-value fix.

## Resolution

The engine stays mark-and-sweep (no true incremental GC), but the *step
contract* is now conformant. Added `global_State.gc_step_accum` and made
`lua_gc` `LUA_GCSTEP` accumulate `arg` work units, running a full
mark-and-sweep collection only when the accumulator reaches the step budget
(`gcparams[LUA_GCPSTEPMUL]`, default 200), returning 1 for a completed cycle
and 0 otherwise. `LUA_GCCOLLECT` resets the accumulator. So
`collectgarbage("step", n)` is proportional to `n` and `dosteps(10) <
dosteps(2)` holds (20 vs 100 steps with the default stepmul).

- `lua/testes/gc.lua` now passes the steps section and proceeds to line 249,
