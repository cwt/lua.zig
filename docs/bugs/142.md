# BUG-142 — `coroutine.close` on Running Thread Destroys Active `CallInfo` Causing UAF and Double-Free

- **Severity:** `CRITICAL`
- **Status:** ✅ FIXED
- **Location:** `src/lib/corolib.zig:145-152` (`luaB_close`), `src/lua.zig:892-902` (`precall`), `src/lua.zig:2410-2415` (`lua_closethread`)

## Defect Summary

In `src/lib/corolib.zig`:
```zig
COS_RUN => {
    _ = try lua.lua_geti(L, lua.LUA_REGISTRYINDEX, llimits.LUA_RIDX_MAINTHREAD);
    if (lua.lua_tothread(L, -1)) |main| {
        if (main == co) return lauxlib.luaL_error(L, "cannot close main thread");
    }
    _ = lua.lua_closethread(co, L);
    return 0;
},
```

When a running coroutine invokes `coroutine.close(coroutine.running())`:
1. `co == L`. It is not the main thread, so execution reaches `lua_closethread(co, L)`.
2. `lua_closethread` invokes `freeAllCallInfos(L)`, freeing every `CallInfo` struct linked on `L` and resetting `L.ci = &L.base_ci`.
3. If `luaB_close` returns normally into `precall`, `precall` accesses the deallocated `new_ci` and calls `freeCallInfo(L, new_ci)`, leading to UAF, double-free, and continuation into dead interpreter frames.

## Fix Implemented

1. In `src/lib/corolib.zig` (`luaB_close`), `COS_RUN` executes `lua_closethread(co, L)` and returns `error.ThreadClosed`.
2. In `src/lua.zig` (`precall`), `error.ThreadClosed` from `cc.f(L)` is immediately returned without touching `new_ci` or calling `poscall`/`freeCallInfo`.
3. In `src/lua.zig` (`lua_pcallk`), `error.ThreadClosed` bypasses pcall boundaries and propagates upward (matching Lua reference `luaD_throwbaselevel`).
4. In `src/lua.zig` (`unroll`, `do_resume`, `lua_resume`), `error.ThreadClosed` is caught at the coroutine resume boundary.
5. In `src/lua.zig` (`lua_closethread`), clean termination resets `L.top = 1; L.status = LUA_OK; return LUA_OK;` so `lua_gettop(co) == 0` and the coroutine transitions cleanly to `dead`.
