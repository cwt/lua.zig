# BUG-142 — `coroutine.close` on Running Thread Destroys Active `CallInfo` Causing UAF and Double-Free

- **Severity:** `CRITICAL`
- **Status:** ⏳ OPEN
- **Location:** `src/lib/corolib.zig:145-152` (`luaB_close`), `src/lua.zig:923-928` (`precall`), `src/lua.zig:2362` (`lua_closethread`)

## Defect Summary

In `src/lib/corolib.zig`:
```zig
COS_RUN => {
    _ = try lua.lua_geti(L, lua.LUA_REGISTRYINDEX, llimits.LUA_RIDX_MAINTHREAD);
    if (lua.lua_tothread(L, -1)) |main| {
        if (main == co) return lauxlib.luaL_error(L, "cannot close main thread");
    }
    _ = lua.lua_closethread(co, L);
    return 0;
},
```

When a running coroutine invokes `coroutine.close(coroutine.running())`:
1. `co == L`. It is not the main thread, so execution reaches `lua_closethread(co, L)`.
2. `lua_closethread` invokes `freeAllCallInfos(L)` (line 2362), freeing every `CallInfo` struct linked on `L` and setting `L.ci = null`.
3. `luaB_close` returns `0` back to `precall` in `src/lua.zig:923-928`:
   ```zig
   try poscall(L, new_ci, first_result, num_returned);
   L.ci = old_ci;
   if (old_ci) |prev| {
       prev.next = null;
   }
   freeCallInfo(L, new_ci);
   return null;
   ```
4. `new_ci` and `old_ci` were already deallocated inside `freeAllCallInfos(L)`.
5. `poscall` accesses memory within the deallocated `new_ci` (Use-After-Free).
6. `freeCallInfo(L, new_ci)` destroys `new_ci` again (Double-Free).

In standard Lua (PUC-Rio 5.4 / 5.5), a running coroutine cannot close itself directly via `coroutine.close(running)` without raising an error (`"cannot close a running coroutine"`).

## Impact

Any Lua code that attempts to close the running coroutine triggers memory corruption, allocator panic, or segmentation fault due to UAF and double-free in the C-call return unwinding path.

## Proposed Fix

Disallow closing a coroutine if `co == L`, matching the reference behavior:
```zig
if (co == L) {
    return lauxlib.luaL_error(L, "cannot close a running coroutine");
}
```
