# BUG-160 — Yield From a Resumed Coroutine Metamethod Chain Mis-Tracked

- **Severity:** `HIGH`
- **Status:** ❌ FALSE POSITIVE / NOT A BUG
- **Location:** `src/lvm.zig` (resume continuation path) / `src/lua.zig` (`noyield` counter) / `src/ltm.zig` (metamethod dispatch)
- **Upstream test:** `lua/testes/big.lua:56`

## Defect Summary (Original Report)

The original report claimed that `big.lua` fails at line 56 with:

```
[C]: in global 'error'
[C]: in field 'yield'
big.lua:56: in main chunk
luazig: big.lua: attempt to yield from outside a coroutine
```

The report suspected that yield-eligibility tracking was lost along the resume → metamethod dispatch path.

## Why It Is a False Positive

1. **`big.lua` harness requirement:**
   `big.lua` contains an intentional top-level `coroutine.yield'b'` at line 56:
   ```lua
   f, X = nil
   coroutine.yield'b'
   ```
   In the upstream test suite, `big.lua` is never run directly as a standalone script; it is explicitly invoked inside a coroutine wrapper by `all.lua:180`:
   ```lua
   local f = coroutine.wrap(assert(loadfile('big.lua')))
   assert(f() == 'b')
   assert(f() == 'a')
   ```

2. **Identical behavior in the C reference:**
   Running `big.lua` standalone with the PUC-Rio C Lua 5.5.1 reference binary (`lua/lua lua/testes/big.lua`) fails identically:
   ```
   testing large tables
   lua/lua: attempt to yield from outside a coroutine
   stack traceback:
   	[C]: in field 'yield'
   	lua/testes/big.lua:56: in main chunk
   	[C]: in ?
   ```

3. **Metamethod yielding in coroutines works:**
   The metamethod yielding tested earlier in `big.lua` (lines 28–42):
   ```lua
   setmetatable(env, {
     __index = function (t, n) coroutine.yield('g'); return _G[n] end,
     __newindex = function (t, n, v) coroutine.yield('s'); _G[n] = v end,
   })
   local co = coroutine.wrap(f)
   assert(co() == 's')
   assert(co() == 'g')
   assert(co() == 'g')
   assert(co() == 0)
   ```
   executes and passes completely in `luazig`. When run wrapped in a coroutine wrapper as designed (`all.lua:180`), `big.lua` runs to completion and exits successfully.

4. **Dedicated verification:**
   Added a dedicated unit test in `tests/test_basic.zig` (`BUG-160: metamethod yielding inside coroutine (__index and __newindex)`) verifying that yields from `__index` and `__newindex` inside coroutines resume properly with expected return values.

## Resolution

Marked as FALSE POSITIVE / NOT A BUG. No runtime bug exists; the observed failure was an artifact of running a coroutine-harness-dependent test file standalone without its enclosing wrapper.
