# BUG-126 — `luaL_ref` / `luaL_unref` free-list divergences

- **Severity:** [MED]
- **Status:** ⏳ OPEN

- **Location:** `src/lauxlib.zig:556-606`.
- **Defect:**
  1. On first use `luaL_ref` eagerly writes `t[1] = 0` (freelist-empty sentinel).
     In the reference, slot 1 does not exist until the first unref, so the first
     reference lands in slot 1 (`ref = rawlen+1`). Port numbering therefore starts
     at 2 and the sentinel entry is visible to `pairs(t)` / counted by
     `lua_rawlen` on any user-supplied table.
  2. `luaL_unref` early-outs only for `ref < 0`; `ref == 0` proceeds to write
     `t[0] = old_head` and `t[1] = 0`. C ignores every `ref <= 0`
     (`lauxlib.c`: `if (ref >= 0)` guard is absent in port form), leaving the
     freelist intact.
- **Impact:** Observable divergence for embedders comparing behavior against the
  reference (registry ref numbers appear in debug output and error messages);
  stray `[1]=0` entry pollutes iteration of tables passed to `luaL_ref`;
  `unref(L, t, 0)` corrupts the freelist head.
- **Proposed fix:** Drop the eager sentinel (treat "slot 1 not a positive number"
  as empty list exactly like C) and change the guard to `ref <= 0`.
