# BUG-121 — `lua.zig`: `__gc` resurrection unsupported → use-after-free

- **Severity:** [HIGH]
- **Status:** ⏳ OPEN

- **Location:** `src/lua.zig:5130-5182` (`callFinalizer`, relink at 5177-5181);
  sweep logic at `src/lua.zig:5007-5034`.
- **Defect:** After invoking `__gc`, the object is unconditionally relinked into
  `allgc` with `finalized = true; color = .white`, so the next collection frees
  it. The C reference distinguishes GCSFINALIZED from GCSDEAD precisely so a
  finalizer can resurrect the object (store it in a reachable table); only then
  does it become collectible again (without re-running `__gc`). Related gap: if
  `__close`/`__gc` errors occur they are logged via `std.debug.print` and dropped
  rather than surfaced per the reference's `finalizererror` semantics.
- **Impact:** Any Lua idiom that rescues an object inside `__gc` (caches,
  pools, "revive on last release" patterns) ends up with a live table entry
  pointing at freed memory → use-after-free on next access. Silent corruption,
  no error.
- **Proposed fix:** After running the finalizer, re-mark the object and check
  reachability before deciding to free; implement a two-state (finalized vs
  dead) lifecycle matching `lgc.c`.
