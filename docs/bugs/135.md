# BUG-135 — `OP_SETLIST` per-element `setInt` instead of preallocated direct stores

- **Severity:** [MED]
- **Status:** ✅ FIXED

- **Location:** `src/lvm.zig:1780-1800`; reference `lua/lvm.c:1907-1930`.
- **Defect:** C computes `last += n`, calls `luaH_resizearray(h, last)` once when
  needed, then writes each value straight into the array slot (`obj2arr`) with a
  barrier. The port was looping `ltable.setInt(h, idx, val)` for every element — each
  call re-evaluating array bounds, the `u == len+1` append-promotion branch,
  `clearHashKey`, and possible hash fallbacks.
- **Impact:** Table-constructor-heavy code (`{...}` with many elements,
  `{f()}` spreads) pays avoidable per-element overhead versus the reference.
- **Proposed fix:** Add a raw bulk-append entry point to `ltable`
  (preallocate to `last`, then copy), mirroring the reference shape.
- **Fix:** Added `ltable.ensureArraySize` in `src/ltable.zig` to preallocate the array part once in `OP_SETLIST` and perform direct slice writes (`h.array.items[last - 1] = val`), matching `lua/lvm.c:1907-1934`. Added unit tests in `tests/test_basic.zig`.
