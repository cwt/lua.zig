# BUG-153 — Swallowed Error via Dummy `catch {}` in `luaL_tolstring` Violating Rule §0.1 Item 12

- **Severity:** `MED`
- **Status:** ⏳ OPEN
- **Location:** `src/lauxlib.zig:331-335` (`luaL_tolstring`)

## Defect Summary

In `src/lauxlib.zig`:
```zig
pub fn luaL_tolstring(L: *lua.lua_State, idx: i32, len: ?*usize) ?[]const u8 {
    const abs_idx = lua.lua_absindex(L, idx);
    if ((luaL_callmeta(L, abs_idx, "__tostring") catch 0) != 0) {
        if (lua.lua_isstring(L, -1) == 0) {
            // BUG-100: propagate the error instead of swallowing it.
            _ = luaL_error(L, "'__tostring' must return a string") catch {};
        }
        return lua.lua_tolstring(L, -1, len);
    }
```

Notice the comment explicitly notes:
`// BUG-100: propagate the error instead of swallowing it.`
Yet the very next line contains:
`_ = luaL_error(L, "'__tostring' must return a string") catch {};`

In Zig, `luaL_error` returns `error.LuaError`. The `catch {}` block intercepts and discards the error completely.
Execution then falls through to `lua.lua_tolstring(L, -1, len)` on a value that has already been verified **not to be a string**.

## Impact

Directly violates mandatory rule §0.1 item 12: *"Never swallow runtime errors with empty or dummy catch blocks."*
When `__tostring` returns a non-string, the error is suppressed, returning `null` or attempting invalid string conversions.

## Proposed Fix

Propagate the error or raise it cleanly through the Lua error mechanism so that the call aborts as intended.
