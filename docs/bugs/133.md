# BUG-133 — Residual swallowed-error inventory (~90 sites)

- **Severity:** [LOW]
- **Status:** ⏳ OPEN

- **Location:** `rg -n "catch \{\}|orelse \{\}" src/` → 94 hits at audit time.
  Representative clusters:
  - `src/lib/iolib.zig:89,268,277` — `child.wait(...) catch {}` discards spawn
    failure details when a popen pipe fd is missing; zombies/status lost.
  - `src/lua.zig:3586-3610` (`lua_pcallk` precall-failure handling) —
    `_ = luaG_errormsg(L) catch {}` around the error-object/message dispatch:
    if the user error handler itself errors, the `LUA_ERRERR` escalation is
    silently dropped and an arbitrary stale error object surfaces.
  - `src/lib/iolib.zig:257,270,279,303,309` and similar —
    `_ = lua.lua_pushstring(...) orelse {}` where OOM during message creation is
    ignored (acceptable as last-resort per C convention, but undocumented).
  - `src/lundump.zig:349` — registry anchor cleanup marked "best-effort" with a
    swallowed error (BUG-100 follow-up).
  - CLI stderr writers in `src/luazig.zig:140-150` — legitimate best-effort.
- **Defect:** §0.1 rule 12 prohibits empty/dummy catches. Many of these are
  defensible best-effort paths, but they are unclassified: nothing distinguishes
  intentional best-effort from accidental swallowing.
- **Impact:** Error-context loss in rare paths; audit noise — future sweeps
  cannot separate policy from oversight without per-site justification comments.
- **Proposed fix:** Triage all sites into (a) propagate via `try`, (b) real
  fallback with comment citing the C reference behavior, or (c) explicit
  `catch { /* best-effort: ... */ }` annotations; delete the rest.
