# BUG-143 — `growStack(L, 1)` Is a No-Op Bug Causing Latent Out-of-Bounds Stack Panics

- **Severity:** `HIGH`
- **Status:** ✅ FIXED
- **Location:** `src/lua.zig:1305` (`lua_pushvalue`), `src/lua.zig:2063` (`lua_pushexternalstring`), `src/lua.zig:2113, 2133` (`lua_pushcclosure`), `src/lua.zig:2357` (`lua_newthread`), `src/lua.zig:3192` (`lua_getfield`), `src/lua.zig:3211` (`lua_geti`)

## Defect Summary

The implementation of `growStack` in `src/lua.zig` is:
```zig
pub fn growStack(L: *lua_State, needed: usize) !void {
    if (needed <= L.stack.len) return;
    ...
```
`needed` specifies the **absolute required stack capacity** (e.g. `L.top + 1`).

However, multiple C-API functions invoked `growStack(L, 1)`:
- `lua_pushvalue`: `growStack(L, 1) catch return;`
- `lua_pushcclosure`: `growStack(L, 1) catch return;`
- `lua_newthread`: `try growStack(L, 1);`
- `lua_getfield`: `growStack(L, 1) catch return LUA_TNIL;`
- `lua_geti`: `growStack(L, 1) catch return LUA_TNIL;`

Because `L.stack.len` is always at least `BASIC_STACK_SIZE` (40), the check `if (1 <= L.stack.len) return;` was **always true**. `growStack(L, 1)` returned immediately without allocating or growing anything.

In addition, two stack write paths performed zero capacity checks:
- `lua_pushcclosure` cached-hit path
- `lua_pushexternalstring`

Furthermore, `lua_pushvalue`, `lua_getfield`, and `lua_geti` previously called `idxPtr` before `growStack`, which could lead to use-after-free if stack reallocation moved the buffer.

## Fix Implemented

1. Changed `growStack(L, 1)` to `growStack(L, L.top + 1)` across `lua_pushvalue`, `lua_pushcclosure`, `lua_newthread`, `lua_getfield`, and `lua_geti`.
2. Added `growStack(L, L.top + 1)` check to `lua_pushexternalstring` and the `lua_pushcclosure` cached-hit path.
3. Reordered `growStack(L, L.top + 1)` before `idxPtr` in `lua_pushvalue`, `lua_getfield`, and `lua_geti` to prevent dangling pointer access upon stack reallocation.
