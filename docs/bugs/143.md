# BUG-143 — `growStack(L, 1)` Is a No-Op Bug Causing Latent Out-of-Bounds Stack Panics

- **Severity:** `HIGH`
- **Status:** ⏳ OPEN
- **Location:** `src/lua.zig:1371-1379` (`growStack`), called at:
  - `src/lua.zig:1303` (`lua_pushvalue`)
  - `src/lua.zig:2130` (`lua_pushcclosure`)
  - `src/lua.zig:2349` (`lua_newthread`)
  - `src/lua.zig:3202` (`lua_getfield`)
  - `src/lua.zig:3221` (`lua_geti`)

## Defect Summary

The implementation of `growStack` in `src/lua.zig` is:
```zig
pub fn growStack(L: *lua_State, needed: usize) !void {
    if (needed <= L.stack.len) return;
    ...
```
`needed` specifies the **absolute required stack capacity** (e.g. `L.top + 1`).

However, multiple C-API functions invoke `growStack(L, 1)`:
- `lua_pushvalue`: `growStack(L, 1) catch return;`
- `lua_pushcclosure`: `growStack(L, 1) catch return;`
- `lua_newthread`: `try growStack(L, 1);`
- `lua_getfield`: `growStack(L, 1) catch return LUA_TNIL;`
- `lua_geti`: `growStack(L, 1) catch return LUA_TNIL;`

Because `L.stack.len` is always at least `BASIC_STACK_SIZE` (40), the check `if (1 <= L.stack.len) return;` is **always true**. `growStack(L, 1)` returns immediately without allocating or growing anything.

In addition, two stack write paths perform zero capacity checks:
- `lua_pushcclosure` cached-hit path (`src/lua.zig:2106-2110`)
- `lua_pushexternalstring` (`src/lua.zig:2086`)

## Impact

When the stack top reaches capacity (`L.top == L.stack.len`):
- Functions like `lua_pushvalue`, `lua_getfield`, and `lua_geti` fail to grow the stack.
- The subsequent write `L.stack[L.top] = ...` triggers a Zig runtime out-of-bounds slice indexing panic.

## Proposed Fix

Update the call sites to pass the required total capacity `L.top + 1`:
```zig
growStack(L, L.top + 1) catch ...;
```
And add boundary checks to `lua_pushexternalstring` and the `lua_pushcclosure` cache-hit path.
