# BUG-165 — Default `package.cpath` Lacks the `lua/<version>` C-Directory Components

- **Severity:** `MED`
- **Status:** ✅ RESOLVED
- **Location:** `src/lib/loadlib.zig` (default path construction) and
  `src/luaconf.zig` (`LUA_CDIR`-equivalent defaults)
- **Upstream failure:** `lua/testes/main.lua:193`

## Defect Summary

The reference builds the default `package.cpath` from `LUA_CDIR`
(`lua/luaconf.h`; e.g. `/usr/local/lib/lua/5.5/`):

```
./?.so;/usr/local/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so
```

The port emits (verified 2026-09-08):

```
$ luazig -e 'print(package.cpath)'
//!?.so;//!loadall.so;./?.so
```

The `!`-expanded components are missing the `lua/5.5/` subdirectory, so the
default cpath contains no `lua` substring at all. Upstream `main.lua:193`
asserts `string.find(defaultCpath, "lua")` (the "paths did not change"
sanity check after the `-E` test) and fails.

Note: the *mechanics* of `-E` itself are correct — `LUA_PATH=xxx LUA_CPATH=xxx
luazig -E script` prints default paths without `xxx` (BUG-129's fix works);
only the *default value* of cpath diverges.

## Impact

1. `main.lua:193` fails (also the reason `all.lua` fails, since it runs
   `main.lua`).
2. Native modules installed in the versioned C directory
   (`.../lib/lua/5.5/?.so`) would not be found by `require` out of the box.

## Resolution

Mirrored the reference POSIX `lua/luaconf.h` defaults in `src/luaconf.zig`:

- Added `LUA_ROOT = "/usr/local/"` and rebuilt `LUA_LDIR` / `LUA_CDIR` as the
  reference's versioned subdirectories:
  - `LUA_LDIR = "/usr/local/share/lua/5.5/"`
  - `LUA_CDIR = "/usr/local/lib/lua/5.5/"`
- `LUA_PATH_DEFAULT` / `LUA_CPATH_DEFAULT` now expand to the reference strings:
  - path: `/usr/local/share/lua/5.5/?.lua;…/init.lua;/usr/local/lib/lua/5.5/?.lua;…;./?.lua;./?/init.lua`
  - cpath: `/usr/local/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so;./?.so`

Both now contain the literal `lua` and the version `5.5`, so
`main.lua:193`'s `string.find(path, "lua")` / `string.find(cpath, "lua")`
sanity checks pass. The `!` (LUA_EXEC_DIR) substitution mechanism is kept for
user-configured paths; it is simply no longer the basis of the *defaults*.

## Verification

- `package.cpath` now prints `/usr/local/lib/lua/5.5/?.so;…/loadall.so;./?.so`.
- `luazig lua/testes/main.lua` now proceeds past line 193 (the "paths did not
  change" assert). It next fails at line 206, the 5.5.1 `LUA_READLINELIB`
  warning feature — a separate missing feature, tracked as
  [BUG-170](170.md).
- New unit test `BUG-165` in `tests/test_basic.zig` asserts the versioned
  `lua/5.5` components and `loadall.so` in the defaults.
- `./run_testes.sh` → 20 PASS / 0 FAIL / 0 CRASH.
