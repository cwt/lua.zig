# BUG-165 — Default `package.cpath` Lacks the `lua/<version>` C-Directory Components

- **Severity:** `MED`
- **Status:** ❌ OPEN
- **Location:** `src/lib/loadlib.zig` (default path construction) and
  `src/luaconf.zig` (`LUA_CDIR`-equivalent defaults)
- **Upstream failure:** `lua/testes/main.lua:193`

## Defect Summary

The reference builds the default `package.cpath` from `LUA_CDIR`
(`lua/luaconf.h`; e.g. `/usr/local/lib/lua/5.5/`):

```
./?.so;/usr/local/lib/lua/5.5/?.so;/usr/local/lib/lua/5.5/loadall.so
```

The port emits (verified 2026-09-08):

```
$ luazig -e 'print(package.cpath)'
//!?.so;//!loadall.so;./?.so
```

The `!`-expanded components are missing the `lua/5.5/` subdirectory, so the
default cpath contains no `lua` substring at all. Upstream `main.lua:193`
asserts `string.find(defaultCpath, "lua")` (the "paths did not change"
sanity check after the `-E` test) and fails.

Note: the *mechanics* of `-E` itself are correct — `LUA_PATH=xxx LUA_CPATH=xxx
luazig -E script` prints default paths without `xxx` (BUG-129's fix works);
only the *default value* of cpath diverges.

## Impact

1. `main.lua:193` fails (also the reason `all.lua` fails, since it runs
   `main.lua`).
2. Native modules installed in the versioned C directory
   (`.../lib/lua/5.5/?.so`) would not be found by `require` out of the box.

## Proposed Fix

Mirror `lua/luaconf.h` defaults in the path construction: include the
versioned C-dir components (`<sysdir>/lua/5.5/?.so` and
`<sysdir>/lua/5.5/loadall.so`) in the default cpath (and audit the default
`package.path` for the same `LUA_LDIR` components).
