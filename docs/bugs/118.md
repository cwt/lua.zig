# BUG-118 — `ltable.zig`: `clearHashKey` breaks chained-scatter invariants

- **Severity:** [CRITICAL]
- **Status:** ⏳ OPEN

- **Location:** `src/ltable.zig:175-180` (`clearHashKey`), `src/ltable.zig:357-359`
  (`setHash` main-position overwrite), `src/ltable.zig:362-384` (`getFreePos`
  slot reuse); trigger path `src/ltable.zig:318-321` (`setInt` array-append
  promotion); same hazard in weak-table clearing `src/lua.zig:4948-4956`.
- **Defect:** `clearHashKey` sets node `key = .nil` **and** `val = .nil` while
  leaving `.next` intact. In the C reference a deleted entry keeps its key
  (`finishnodeset` only empties the value, `lua/ltable.c:1048-1057`) precisely so
  `getfreepos` (`lua/ltable.c:828-844`, requires `keyisnil`) never hands out a
  node that other chains may pass through. In the port, a cleared node becomes
  reusable while predecessor nodes may still point to it:
  1. `setHash` line 357 places a new key whose main position is the cleared slot,
     overwriting the whole node including `.next = -1`;
  2. `getFreePos` can return a cleared mid-chain slot, and lines 378/382 then
     overwrite its `.next`.
  Any live chain routed through that node is truncated; the orphaned entries
  become unreachable for lookup **and** `pairs`.
- **Trigger:** `setInt` calls `clearHashKey` whenever integer key `k ==
  array.items.len + 1` already lives in the hash part — i.e. ordinary sequential
  filling (`t[1..n]`) after a sparse insert promotes the sparse key out of the
  hash part. A later insertion colliding onto that freed index loses data
  silently. Weak-table clearing produces identical nil-keyed pass-through nodes.
- **Impact:** Silent, permanent loss of table entries (lookup misses, `pairs`
  skips, `#` borders shift) with no error. Rare in small-table fuzzing because it
  requires a hash collision to land exactly on a cleared slot, but reachable from
  ordinary Lua code.
- **Proposed fix:** Mirror the reference: on deletion keep the key and only empty
  the value (dead-key tombstones), or fully relink predecessor chains when
  clearing/reusing any node.
